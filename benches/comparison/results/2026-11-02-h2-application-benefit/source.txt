Paced load:
Five paired rounds at each offered rate in settings.txt alternate executable order.
Each executes: taskset -c 8 BINARY URL paced RATE 3 64.
The harness assigns each worker a scheduled start per request and records scheduling lag and service duration separately.
Corrected latency is scheduling lag plus service duration, not service time alone.
Scheduling lag is producer backlog, not a direct measurement of an internal library queue.
Workers execute their full planned request count and drain after the nominal scheduling period if behind.
The exact planned count is floor(RATE * 3 / 64) * 64; therefore completed count can differ slightly from RATE * 3.
50 of 50 executions exited successfully and completed the exact planned count; every response status and body was checked by the client.
This does not independently count transport errors hidden by successful retries.
paced-rows.txt preserves the PACED output and exit status for every execution.
paced-perf.txt contains task-clock and user-instruction observations from the matching perf stat outputs.
Paced CPU cost includes warmup, generation, collection, quantile sorting, and reporting; it is not isolated HTTP execution cost.
